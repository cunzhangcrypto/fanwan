# 🔔 饭碗儿 · 留言提醒配置教程

> 有人在你碗儿头投了一口（带留言），第一时间喊你。
> 四条通道：**企业微信机器人 / Server酱 / Telegram / 邮箱**，随便填哪条都行，也可以全填。

---

## 0. 先搞懂一件事：谁配什么

这是最容易搞混的地方。四条通道里，**只有 Telegram 需要部署者动手**，其余三条都是碗主人自己配。

| 通道 | 谁配 | 在哪儿配 | 要填的东西 | 平台要不要配密钥 |
|---|---|---|---|---|
| 🔵 企业微信机器人 | 碗主人 | 编辑碗 → 留言提醒 | 群机器人 Webhook 地址 | ❌ 不用 |
| 🟢 Server酱 | 碗主人 | 编辑碗 → 留言提醒 | SendKey（SCT 开头） | ❌ 不用 |
| 🔷 Telegram | **部署者 + 碗主人** | 部署者配 Secret / 碗主人填 chat_id | Bot Token（部署者）、chat_id（碗主人） | ✅ **要** |
| 📮 邮箱 | 碗主人 | 编辑碗 → 留言提醒 | 收件邮箱 + 邮件 API 地址 + API Key + 发件人 | ❌ 不用（走碗主人自己的额度） |

> **不配会怎样？** 完全不影响其他功能。只是碗主人填了对应通知方式也发不出去——而且**失败是静默的**，不会报错、不会重试。所以配完一定要自己验一遍（见第 6 节）。

### ⚡ 30 秒选哪条

| 你的情况 | 推荐 |
|---|---|
| 想最快收到、手机上弹得最明显 | 🟵 **企业微信机器人**（1 分钟搞定） |
| 不想装企业微信，只想在个人微信里收 | 🟢 **Server酱**（但免费版每天只有 5 条） |
| 本来就在用 Telegram | 🔷 **Telegram**（需部署者先配好 Bot Token） |
| 想发到 QQ 邮箱 / 平时就靠邮件 | 📮 **邮箱（Resend）**（有坑，见第 5 节） |

## 1. 前置：先拿到「编辑碗」的入口

所有配置都在 **编辑碗 → 🔔 留言提醒** 里填。进不去编辑页，后面都白说。

| # | 步骤 | 说明 |
|---|---|---|
| 1 | 用**摆碗时的那个浏览器**打开饭碗儿详情页 | 编辑令牌存在这个浏览器的 localStorage 里 |
| 2 | 页面下方出现「**改一哈**」按钮 | 这就是编辑入口 |
| 3 | 点「**复制管理链接**」并存到手机备忘录 | 链接形如 `https://你的域名/碗后缀?token=xxx`，**换了设备/浏览器也能进管理界面** |
| 4 | 以后要改配置 | 直接打开这条管理链接，或点碗页的「改一哈」 |

> ⚠️ **丢了令牌就改不了**：令牌只在摆碗时生成一次，服务端不提供找回。所以第 3 步一定要存。
> ⚠️ 通知里给的那条链接是 `https://域名/碗后缀`，**不带令牌**。在没存过令牌的设备上点开只是普通访客视角，看不到「待放行」。所以还是得存管理链接。

## 2. 🔵 企业微信机器人 Webhook（推荐，最快）

**原理**：企业微信内部群可以加「群机器人」，机器人自带一个 Webhook 地址。饭碗儿往这个地址 POST 一条文本，群里就弹消息。

> ⚠️ 注意是**企业微信**，不是普通微信。普通微信群**没有**群机器人这个功能。
> 好消息：企业微信个人也能免费注册，建一个只有自己的群就能用，不用公司、不用认证、不用花钱。

### 步骤表

| # | 操作 | 在哪 |
|---|---|---|
| 1 | 注册企业微信（免费，个人可注册） | [work.weixin.qq.com](https://work.weixin.qq.com) → 立即注册，选「企业/团队」，人数随便填 |
| 2 | 建一个内部群 | 企业微信客户端 → 消息 → 右上角 **+** → 发起群聊 → 拉自己（可以只有自己一个人） |
| 3 | 进群 → 右上角 **⋯** | 群设置页 |
| 4 | 找到「**群机器人**」→ **添加机器人** | 部分版本叫「添加群机器人」 |
| 5 | 起个名字（如「饭碗儿」）→ 添加 | 添加后弹出 Webhook 地址 |
| 6 | **复制 Webhook 地址** | 形如 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` |
| 7 | 打开饭碗儿编辑页 → 留言提醒 → 填进「**企业微信机器人 Webhook**」 | 粘贴整条地址，别漏了 `key=` |
| 8 | 保存 | 搞定 |

### 常见坑

| 坑 | 表现 | 怎么解 |
|---|---|---|
| 用了普通微信 | 微信群设置里根本找不到「群机器人」 | 必须用**企业微信**建群 |
| 复制时漏了 `?key=` | 保存时提示「企业微信机器人地址不对头，要那种 qyapi.weixin.qq.com 开头的」 | 整条复制，从 `https://` 到 key 结尾 |
| 只想推给个人微信 | — | 企业微信群机器人是推到**群**里的；要推个人微信请用 Server酱 |
| 消息太频繁 | 机器人有 **20 条/分钟** 的频率上限 | 饭碗儿场景一天也没几条，正常不会撞 |

> ✅ 优点：1 分钟配完、免费、无每日条数限制、手机上弹得很明显。
> ⚠️ 缺点：得装企业微信（或者至少收得到企业微信消息）。

## 3. 🟢 Server酱（推到个人微信）

**原理**：Server酱是一个「一个 HTTP 请求 = 一条微信消息」的转发服务。你拿一个 SendKey，推送就到了你微信。

### 步骤表

| # | 操作 | 在哪 |
|---|---|---|
| 1 | 打开 [sct.ftqq.com](https://sct.ftqq.com) | 官网 |
| 2 | **微信扫码登录** | 手机微信扫 |
| 3 | 进「**SendKey**」页面，复制你的 SendKey | 形如 `SCT` 开头的字符串 |
| 4 | 进「**微信推送**」页面，**扫码绑定接收消息的微信号** | 这步不做，推送发不出去 |
| 5 | 打开饭碗儿编辑页 → 留言提醒 → 填进「**Server酱 SendKey**」 | 只填 Key 本身，**不要**填网址 |
| 6 | 保存 | 搞定 |

### 常见坑

| 坑 | 表现 | 怎么解 |
|---|---|---|
| 填了完整 API 网址 | 提示「Server酱 SendKey 不对头，SCT 或 SCU 开头」 | 只填 SendKey，别填 `https://sctapi.ftqq.com/` |
| **SendKey 是 `sctp` 开头的** | 保存不了 | ⚠️ 当前版本校验只认 `SCT` / `SCU` 开头。新版 Server酱给的是 `sctp` 开头的 Key，需要把 `src/lib/validate.js` 里的 `isValidServerChanKey`（以及 `static/js/create.js` 里对应那行）的正则补上 `sctp` 分支，同时 `src/lib/notify.js` 的 API 域名要按官方说明改成 `https://{uid}.push.ft07.com/send/{SendKey}.send` |
| 没绑定微信号 | 后台显示发送成功，微信里啥也没有 | 去「微信推送」页面扫码绑定 |
| **免费版每天只有 5 条** | 第 6 条开始就不推了 | 推送频繁就换企业微信机器人，或升级 Server酱订阅会员 |
| 每分钟限 5 条 | 撞上限会失败 | 饭碗儿场景基本不会撞 |

> ✅ 优点：不用装任何 App，个人微信直接收。
> ⚠️ 缺点：**免费版每天 5 条**，碗被投爆了就收不全了。

## 4. 🔷 Telegram（需要部署者先配好 Bot Token）

**原理**：部署者建一个 Bot（全站共用一个），碗主人填自己的 chat_id。投喂时 Worker 调 Telegram Bot API 发消息。

### Part A · 部署者做（一次性，全站共用）

| # | 操作 | 在哪 |
|---|---|---|
| 1 | 在 Telegram 里搜 **@BotFather**，发 `/newbot` | Telegram |
| 2 | 按提示起名（显示名 + 用户名，用户名必须以 `bot` 结尾） | 例：`fanwaner_notify_bot` |
| 3 | 拿到 **Bot Token** | 形如 `7234567890:AAHxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx` |
| 4 | 写进部署密钥 | 见下方二选一 |
| 5 | 重新部署 | Actions → Deploy → Run workflow |

**第 4 步二选一：**

```bash
# 方式一：命令行（作者/开发者）
wrangler secret put TELEGRAM_BOT_TOKEN
# 方式二：GitHub 网页（小白友好）
# Fork 的仓库 → Settings → Secrets and variables → Actions → New repository secret
# Name: TELEGRAM_BOT_TOKEN    Value: 上面拿到的 Token
```

> ⚠️ **没配 Bot Token 会发生什么**：碗主人填了 chat_id 也是静默失败，没有任何提示（代码里是 `if (bowl.notify_telegram && env.TELEGRAM_BOT_TOKEN)`，Token 空着直接跳过）。所以部署者一定要先配。

### Part B · 碗主人做

| # | 操作 | 在哪 |
|---|---|---|
| 1 | **先给这个 Bot 发一条消息**（比如 `/start`） | Telegram 搜到 Bot → 进对话 → 发 `/start` |
| 2 | 搜 **@userinfobot** → 发任意消息 → 拿你的 **ID** | 那个数字就是 chat_id |
| 3 | 打开饭碗儿编辑页 → 留言提醒 → 填进「**Telegram chat_id**」 | 例：`123456789` |
| 4 | 保存 | 搞定 |

> ⚠️ **第 1 步不能跳**：Telegram 规定 Bot 不能主动给没跟它说过话的人发消息。不先 `/start`，推送会失败（`chat not found`）。

### 想推到 Telegram 群？

| # | 操作 |
|---|---|
| 1 | 把这个 Bot **拉进群** |
| 2 | 在群里 @ 一下 Bot（或直接发条消息），让它能看到群 |
| 3 | 用 @userinfobot 把 bot 拉进去后转发消息拿 ID，或用 `https://api.telegram.org/bot<Token>/getUpdates` 查看 `chat.id` |
| 4 | 群 ID 是**负数**，通常是 `-100` 开头（如 `-1001234567890`），对，就把这个负数填进去 |

### 常见坑

| 坑 | 表现 | 怎么解 |
|---|---|---|
| 填的不是纯数字 | 提示「Telegram chat_id 不对头，要纯数字」 | 只填数字；群 ID 是 `-100` 开头的负数，负号要留 |
| 没 `/start` | 静默失败 | 先给 Bot 发条消息 |
| 部署者没配 Token | 静默失败，后台啥也看不出来 | 让部署者配 `TELEGRAM_BOT_TOKEN` 并重新部署 |
| 多个碗主人 | 都共用同一个 Bot，消息都从同一个机器人发出来 | 正常现象，靠填不同 chat_id 区分 |

## 5. 📮 邮箱提醒（Resend，走碗主人自己的额度）

**原理**：饭碗儿**不使用平台自己的邮箱服务**。碗主人在编辑页填一个「Resend 兼容的 HTTP 发信接口」+ 自己的 API Key，平台只负责把通知 POST 过去。**消耗的是碗主人自己的额度，跟部署者莫得关系。**

### 步骤表

| # | 操作 | 在哪 |
|---|---|---|
| 1 | 注册 [resend.com](https://resend.com)（免费，**不用绑卡**） | 用你**想收提醒的那个邮箱**注册 ⚠️ 见下方坑 1 |
| 2 | 左侧 **API Keys** → **Create API Key** | Resend 后台 |
| 3 | 权限选 **Sending** 就够（只发信不管域名） | — |
| 4 | **立刻复制 `re_` 开头的 Key** | ⚠️ 只显示这一次，关了弹窗就再也看不到 |
| 5 | 打开饭碗儿编辑页 → 留言提醒 → **邮箱提醒**区域 | — |
| 6 | 填「**提醒发到哪个邮箱？**」 | 建议和注册 Resend 的邮箱保持一致 |
| 7 | 填「**发信通道 · API 地址**」 | 填 `https://api.resend.com/emails`（也是默认值） |
| 8 | 填「**发信通道 · API Key**」 | 粘贴第 4 步的 `re_xxx` |
| 9 | 填「**发信通道 · 发件人**」（可选） | 不填默认 `饭碗儿 <onboarding@resend.dev>` |
| 10 | 保存 | 搞定 |

### ⚠️ 三个必须知道的坑

**坑 1（最大的坑）：没验证域名，只能发给你自己**

Resend 未验证自定义域名时，只允许用 `onboarding@resend.dev` 发信，而且**只能发到「注册 Resend 时用的那个邮箱」**。发给别的地址会被拒（403）。

| 你的需求 | 怎么办 |
|---|---|
| 只是自己收提醒 | 把「收件邮箱」填成**注册 Resend 的那个邮箱**，就这一条，不用验证域名 |
| 想发到任意邮箱（如 QQ 邮箱 ≠ Resend 注册邮箱） | **必须验证一个自己的域名**，见下方「验证域名步骤」 |

**坑 2：免费额度有限**

| 项 | 数值 |
|---|---|
| 免费额度 | **100 封/天**、3,000 封/月 |
| 速率限制 | 约 2 请求/秒 |
| 免费版 API Key 数量 | 最多 2 个 |
| 超限表现 | **静默丢弃**，不会报错 |

**坑 3：编辑时不回显、不填就保留原值**

API Key 是敏感信息。再次编辑碗的时候，Key 输入框是**空的**——不是丢了，是不回显。**不填 = 保留原来的**，只有填了新的才会覆盖。

另外：`notify_email`、`email_api_url`、`email_api_key` **三个都非空才会发信**。只填了收件邮箱、没配发信通道，是发不出去的。

### 想发到任意邮箱？验证域名步骤

| # | 操作 | 在哪 |
|---|---|---|
| 1 | Resend 后台 → **Domains** → **Add Domain** | 输入你的域名，如 `example.com` |
| 2 | 复制它给出的 DNS 记录（SPF 的 TXT、DKIM 的 CNAME ×2~3、DMARC 的 TXT） | — |
| 3 | 到你的 DNS 服务商添加这些记录 | Cloudflare / 阿里云 / 腾讯云都行 |
| 4 | ⚠️ **DKIM 的 CNAME 必须关掉 Cloudflare 代理（灰色云朵 = DNS only）** | 开着代理验证一定失败 |
| 5 | 主机名**只填前缀**（如 `send`、`resend1._domainkey`） | 填完整域名会变成 `send.example.com.example.com` |
| 6 | 回 Resend 点 **Verify**，等几分钟 | 状态变 `Verified` |
| 7 | 编辑碗 → 发件人填成 `饭碗儿 <noreply@example.com>` | 支持「别名 <邮箱>」格式 |
| 8 | 保存 | 之后就能发到任意收件邮箱了 |

> 🧩 **DNS 依赖提示**：饭碗儿本身就部署在 Cloudflare 上，如果你把域名 NS 也托管在 Cloudflare，加这些记录一步到位，最省事。
> 💡 **不想折腾域名？** 那就直接用企业微信机器人或 Server酱，零成本、零等待、零 DNS。

## 6. ✅ 配完怎么验证（重要，别跳过）

**饭碗儿没有「发送测试通知」按钮**，通知只在有人**真实投一口**的时候触发。而且失败是静默的。

| # | 操作 | 预期 |
|---|---|---|
| 1 | 把碗链接发到手机 / 用无痕窗口打开 | 换个设备，避免被 IP 或缓存影响 |
| 2 | 正常走一遍「**投一口**」，金额填 `0.01` | 需要过 Turnstile 人机验证 |
| 3 | 留言随便写两个字 | — |
| 4 | 提交后**等几秒** | 对应通道应该收到 ✅ |
| 5 | 看后台有没有产生「待放行」记录 | 说明主流程通了（通知和审核是两件事） |
| 6 | 收到的通知长这样 | 见下方样例 |

**通知内容样例：**

```
🍚 有人在你碗儿头留言了！

「路过滴耿直人」说：加油，先吃上饭
金额：¥0.01

快去放行：https://你的域名/碗后缀
```

> 🔎 **关键认识**：通知是在**「投一口」提交的那一刻**发的（钱还没到、还没审核）。所以它的作用是「提醒你去放行」，不是「提醒你收到钱了」。
> 🔒 **隐私**：通知里填的企业微信地址、SendKey、chat_id、邮箱都**只有你能看到**，接口不会返回给访客。

## 7. 🔧 收不到？按这个表排查

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| **一条都没收到，四条通道都没动静** | 碗没保存成功 / 投喂没提交成功 | 看编辑页有没有报错提示；确认后台能看到「待放行」记录 |
| 企业微信没动静 | 填的不是企业微信群机器人地址 | 地址必须以 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=` 开头 |
| 企业微信没动静 | 机器人被移出群 / 群被解散 | 回群设置里确认机器人还在 |
| Server酱没动静 | 没扫码绑定微信号 | 去 sct.ftqq.com「微信推送」页面绑定 |
| Server酱没动静 | 当天 5 条免费额度用完 | 换通道，或等第二天 |
| Telegram 没动静 | 没先给 Bot 发 `/start` | 先发一条消息给 Bot |
| Telegram 没动静 | 部署者没配 `TELEGRAM_BOT_TOKEN` | 让部署者配 + 重新部署 |
| Telegram 没动静 | chat_id 填成了带 `@` 的用户名 | 只能填纯数字 ID |
| 邮件没动静 | 收件邮箱 ≠ Resend 注册邮箱，且没验证域名 | 改成注册邮箱，或验证自己的域名 |
| 邮件没动静 | 只填了收件邮箱，没填 API 地址 / API Key | 三个都要填 |
| 邮件没动静 | 当天 100 封用完了 | 等第二天 |
| 邮件进垃圾箱 | `onboarding@resend.dev` 是共享测试域名，信誉一般 | 验证自己的域名，用自己的发件地址 |
| 编辑时 API Key 是空的 | 正常的，敏感信息不回显 | 不填就是保留原值，不用担心 |
| 保存时提示格式不对 | 见第 8 节的校验规则 | 对着改 |

## 8. 📋 校验规则速查（填之前先看一眼，省得保存不了）

饭碗儿前后端都会校验，格式不对直接拦下。

| 字段 | 规则 | ✅ 正确示例 | ❌ 错误示例 |
|---|---|---|---|
| 企业微信 Webhook | 必须 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=` + 1~80 位字母/数字/横杠 | `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=693a91f6-7xxx-4bc4-97a0-0ec2sifa5aaa` | 填了 Server酱或钉钉的地址 |
| Telegram chat_id | 纯数字，5~15 位，可带负号 | `123456789` / `-1001234567890` | `@myusername` |
| Server酱 SendKey | `SCT` 开头，或 `SCU` 开头 | `SCT123456TcJxxxxxxxx` | `https://sctapi.ftqq.com/xxx.send`；⚠️ `sctp` 开头暂不支持 |
| 收件邮箱 | 标准邮箱格式，≤128 字符 | `you@qq.com` | `you@@qq.com` |
| 邮件 API 地址 | 必须 `https://` 开头 | `https://api.resend.com/emails` | `api.resend.com/emails` |
| 邮件 API Key | ≥6 位，≤128 位 | `re_xxxxxxxxxxxx` | 空着（但至少要 6 位） |
| 发件人 | 纯邮箱，或「别名 <邮箱>」 | `饭碗儿 <noreply@example.com>` | `饭碗儿`（光有名字不行） |

> 四条通道**可以只填一条，也可以全填**，不填的平台就当它不存在，不会报错。

---

## 9. 🔒 安全提示

| 项 | 说明 |
|---|---|
| 这些信息存哪 | 全部存在 D1 数据库的 `bowls` 表里（`notify_wecom` / `notify_telegram` / `notify_serverchan` / `notify_email` / `email_api_url` / `email_api_key` / `email_from`） |
| 会不会泄露 | 不会。编辑页不公开、接口不返回这些字段给访客 |
| 谁能改 | 只有拿到 `editToken` 的碗主人。**管理链接 = 钥匙**，别往外发 |
| API Key 处理 | 编辑时不回显；不填就保留原值；填了才覆盖 |
| 推送失败会怎样 | **静默失败，不重试**（避免重复轰炸你），也绝不拖慢投喂主流程 |
